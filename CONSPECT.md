# Конспект VPd02 — документация и форматы данных

## 1. API и документация

API — способ, которым программы обмениваются данными по сети. REST API задаёт правила:
ресурсы (URL), методы (GET/POST/…), статусы, форматы. Документация описывает:

- **endpoints** — адреса и параметры запросов;
- **методы** — что делает каждый адрес (у нас только GET);
- **формат ответа** — структура JSON и типы полей;
- **аутентификацию** — ключ, OAuth, отсутствие ключа;
- **лимиты** — сколько запросов можно делать.

Порядок работы: читаем документацию → определяем endpoint → делаем запрос → разбираем JSON.

## 2. Форматы данных

| Формат | Где применяется | В Python |
|---|---|---|
| **JSON** | API, конфиги | `json` / `response.json()` |
| **XML** | legacy-сервисы, SOAP | `xml.etree.ElementTree` |
| **FormData** | загрузка файлов | `files=` в `requests` |
| **x-www-form-urlencoded** | HTML-формы | `data=` в `requests` |

JSON — текстовый формат: объекты `{}`, массивы `[]`, строки в двойных кавычках,
числа, `true`/`false`, `null`. Ключи всегда строки. `response.json()` превращает
JSON в `dict`/`list`.

## 3. Open-эндпоинт и ключевые поля

```http
GET https://open.er-api.com/v6/latest/USD
```

Ключ API не нужен. Ответ:

| Поле | Смысл |
|---|---|
| `result` | `success` или `error` |
| `provider`, `documentation`, `terms_of_use` | служебные ссылки |
| `time_last_update_unix` / `_utc` | время обновления курсов |
| `time_next_update_unix` / `_utc` | время следующего обновления |
| `base_code` | базовая валюта |
| `rates` | словарь «код валюты → курс к базе» |

## 3.1. Чей это курс и как считается конвертация

- В запросе только база: `GET /v6/latest/{base}`. Параметра региона, города или банка нет.
  Ответ — один общий набор курсов провайдера `exchangerate-api.com`, одинаковый для всех.
- Время в ответе — UTC (`time_last_update_utc`), обновление примерно раз в сутки.
- Курс ориентировочный (рыночная середина), не курс покупки/продажи банка или обменника:
  банки добавляют наценку, и их курс отличается.
- Конвертация: `amount * rates[to] / rates[from]`. При базе, равной исходной валюте,
  `rates[from] = 1`.

## 4. Разбор кода из материалов и что исправлено

В примерах из курса были ошибки — их важно узнать в лицо:

| В материалах | Проблема | Как правильно |
|---|---|---|
| `URL = "https://open.er-api.com/v6/latest/{currency_code}"` | обычная строка, подстановки нет | `url = f"https://open.er-api.com/v6/latest/{base}"` |
| `if _name__ == "__main_":` | опечатка в служебном имени | `if __name__ == "__main__":` |
| `response. status_code` | пробел внутри выражения | `response.status_code` |
| `print(data); return None` | функция печатает вместо возврата | `return payload` |
| `json.dump(data, file)` | нет `ensure_ascii=False`, `indent=4`, кодировки | `open(..., encoding="utf-8")` + `json.dump(..., ensure_ascii=False, indent=4)` |
| одна проверка `status_code` | неизвестная валюта приходит с HTTP 200 | проверять ещё `result`/`error-type` |
| кэш без TTL и без проверки базы | устаревшие или чужие курсы | проверять mtime (24 ч) и `base_code` |

## 5. Кэширование

- API обновляет курсы раз в сутки, поэтому запрос на каждый запуск избыточен.
- Сохраняем весь ответ в `currency_rate.json`, свежесть определяем по mtime файла.
- Кэш валиден, если файл моложе 24 часов **и** `base_code` совпадает с запрошенной базой.
- `json.dump(..., ensure_ascii=False)` сохраняет кириллицу читаемой; `encoding="utf-8"`
  задаётся у `open()`, у `json.dump()` такого параметра нет.

## 6. UX меню: контекст и действия

- **Состояние над меню.** Пользователь первым делом видит, от какой базы считаем и что
  с данными: `База: USD | кэш 2.4 ч, актуален`. Это дешевле, чем спрашивать базовую
  валюту в каждом пункте.
- **Пункты — действия, а не сущности.** «Показать курсы», «Сменить базовую валюту»,
  «Найти валюту» — понятнее, чем «Курсы» / «Список» / «Кэш».
- **Не спрашивать лишнего.** Для списка валют база не нужна: набор кодов одинаков для любой.
- **Ошибка ведёт дальше.** Сообщение о неверном коде подсказывает пункт, где посмотреть коды.
- **Смена базы проверяется запросом**, чтобы не сохранить несуществующий код.

## 7. Ошибки и их подача

| Ситуация | Что делает код |
|---|---|
| нет сети / таймаут | `CurrencyError` с текстом, без стектрейса |
| HTTP 4xx/5xx | `CurrencyError` с кодом и причиной |
| ответ не JSON | `CurrencyError` «Ответ API не является JSON» |
| неизвестный код валюты | `CurrencyError` с `error-type: unsupported-code` |
| код не похож на валютный (`1`, `US`) | локальная проверка `^[A-Z]{3}$`, запрос не отправляется |
| нет курсов в ответе | `CurrencyError` «нет курсов валют» |
| нет файла кэша | не ошибка: идём в API и создаём файл |

## 8. Модульная структура (версия 2)

Пункт 7 задания — разделение на слои. Реализовано без изменения поведения:

| Модуль | Ответственность | Не знает про |
|---|---|---|
| `api_client.py` | GET-запрос, проверка статуса и тела, `CurrencyError`, `normalize_code` | файлы, меню |
| `storage.py` | `save_to_file`, `read_from_file`, `is_cache_fresh`, TTL | сеть, меню |
| `cli.py` | меню, ввод/вывод, сообщения об ошибках | HTTP и файлы напрямую |
| `currency.py` | `load_rates` (кэш или API), `convert`, точка входа | детали HTTP и JSON-файла |

Обязательные функции остаются доступны из `currency.py` через реэкспорт, поэтому
`python currency.py` и критерии приёмки не меняются. Циклических импортов нет:
`cli` импортирует `currency`, а `currency` подключает `cli` только в точке входа.
